# moskwin-pub

Личный клиент kino.pub для Android TV.

## Состояние

- `core/` — сетевое ядро на чистом Kotlin: список адресов API с автопереключением,
  вход по коду на экране, обновление токена, авторизованные запросы; правила выбора
  озвучки и субтитров по умолчанию и признак «детское» (`Rules.kt`); модели каталога и
  сборка рядов главного экрана (`Models.kt`, `Home.kt`), тест скорости, выбор дорожек для плеера, каталог и профиль. 38 тестов.
- `docs/kinoapi/` — копия официальной документации API (kinoapi.com, снята 2026-11-15).
  Адреса в примерах устарели; рабочий адрес — `https://kino.watch/api`.
- `app/` — приложение для Android TV (Compose for TV): экран входа по коду, хранение токенов,
  главный экран (ряды «Продолжить», детское, новинки по IMDb, переключатель сервера),
  боковое меню, каталог с фильтрами и сортировкой, профиль, карточка с сезонами и
  детскими кнопками, поиск, настройки, плеер (Media3, HLS).
  Проверено на телевизоре с живым сервером.
- `device/` — `deploy.ps1` собирает release-сборку и ставит её на телевизор, `perf.ps1`
  замеряет скорость интерфейса.

## Проверка и сборка

```
gradlew :core:test
gradlew :app:assembleDebug
```

Сборка идёт через Gradle wrapper (8.11.1) и требует JDK 17–21 в `JAVA_HOME`:
JBR из Android Studio (Java 25) не подходит.

APK: `app/build/outputs/apk/debug/app-debug.apk`. Перед сборкой в `local.properties`
(в репозиторий не попадает) нужны три строки:

```
sdk.dir=<путь к Android SDK>
kinopub.clientId=xbmc
kinopub.clientSecret=<ключ Kodi-плагина>
```

Без ключа приложение запускается и показывает сообщение, что ключ не задан.

## APK в репозитории

`apk/kino-pub.apk` — release-сборка, на которую ведёт ссылка в `README.md`; рядом
`apk/version.json` с номером версии. В сборку зашит ключ клиента из `local.properties`:
репозиторий открытый, и ключ доступен всем, кто скачает APK.
Снимки экрана для `README.md` лежат в `docs/screenshots/`.

## Выпуск новой версии

Установленные приложения при запуске читают `apk/version.json` из ветки `main` и, если
`versionCode` там больше своего, предлагают обновиться и скачивают `apk/kino-pub.apk`.
Сборка берёт номер версии из того же файла. Порядок выпуска:

1. Увеличить `versionCode` и `versionName` в `apk/version.json`, в `notes` — что нового:
   это список изменений, который человек видит перед установкой, по строке на пункт.
2. `pwsh -File device\release.ps1` — тесты, сборка, копия в `apk/kino-pub.apk`.
3. Закоммитить `apk/` и отправить в `main`.

Имя репозитория, ветки и этих двух файлов зашито в установленные приложения
(`Updater.kt`): переименовать их — значит оставить всех без обновлений.

## Ключ подписи

Android ставит обновление поверх только если оно подписано тем же ключом, что и
установленная сборка. Ключ лежит вне репозитория; в `local.properties` на него
указывают три строки:

```
signing.store=<путь к файлу ключа>
signing.alias=<имя ключа в файле>
signing.password=<пароль>
```

Файл ключа и пароль нужно хранить в копии: без них нельзя выпустить обновление,
которое встанет поверх, — всем придётся удалять приложение и входить заново.
Без этих строк сборка подписывается отладочным ключом Android: она работает, но
поверх выпущенной версии не ставится.
