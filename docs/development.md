# Сборка и устройство проекта

Приложение для Android TV на Kotlin: интерфейс на Compose for TV, плеер на Media3
(ExoPlayer, HLS), сеть на OkHttp. Что приложение умеет — в [README](../README.md).

## Из чего состоит

| Папка | Что в ней |
|---|---|
| `core/` | Всё, что не зависит от Android: запросы к API kino.pub, вход по коду, модели, сборка рядов главного экрана, правила выбора озвучки и субтитров, разбор субтитров, проверка обновлений. Чистый Kotlin, покрыт тестами. |
| `app/` | Само приложение: экраны, плеер, настройки, обновление. |
| `apk/` | Выпущенная сборка и файл с номером версии. Отсюда приложение скачивают люди и отсюда же оно обновляется. |
| `device/` | Скрипты: установка на телевизор, выпуск версии, замер скорости интерфейса, рисование значка. |
| `docs/` | Эта страница, снимки экрана для README и копия документации API (`docs/kinoapi/`). |

Экраны приложения лежат в `app/src/main/kotlin/pub/moskwin/tv/`, по файлу на экран:

| Файл | Экран |
|---|---|
| `MainActivity.kt` | Запуск, переходы между экранами, кнопка «назад» |
| `SideMenu.kt` | Боковое меню и логотип |
| `LoginScreen.kt` | Вход по коду |
| `HomeScreen.kt` | Главный экран с рядами |
| `CatalogScreen.kt`, `SearchScreen.kt` | Каталог с фильтрами и поиск |
| `FolderScreen.kt` | «Посмотрю позже» и раздел ребёнка |
| `DetailsScreen.kt` | Карточка фильма или сериала |
| `PlayerScreen.kt` | Плеер, его плашка и настройки |
| `SettingsScreen.kt`, `ProfileScreen.kt` | Настройки и профиль |
| `Updater.kt` | Проверка и установка обновлений |
| `Glass.kt`, `Cards.kt`, `Panels.kt`, `Icons.kt` | Общие детали оформления: кнопки, карточки, панели, значки |

## Что нужно для сборки

- **JDK 17–21** в `JAVA_HOME`. JBR из свежей Android Studio (Java 25) не подходит.
- **Android SDK** с платформой 35.
- Gradle ставить не нужно: в проекте лежит своя обёртка (`gradlew`).
- Файл **`local.properties`** в корне проекта. В репозиторий он не попадает, его нужно
  создать самому:

```
sdk.dir=<путь к Android SDK>
kinopub.clientId=<идентификатор клиента kino.pub>
kinopub.clientSecret=<ключ клиента kino.pub>
```

Идентификатор и ключ клиента выдаёт kino.pub; своих в репозитории нет. Без них
приложение собирается, но при запуске показывает сообщение, что ключ не задан.

## Команды

```
gradlew :core:test
```

Тесты ядра. Android для них не нужен.

```
gradlew :app:assembleRelease
```

Оптимизированная сборка: `app/build/outputs/apk/release/app-release.apk`. На телевизор
ставить нужно её. Отладочная (`:app:assembleDebug`) работает в несколько раз медленнее.

```
pwsh -File device\deploy.ps1
```

Собирает и ставит сборку на телевизор по сети через adb, затем заранее компилирует её
на устройстве, чтобы интерфейс не тормозил первые минуты. Адрес телевизора — параметр
`-Tv`.

## Выпуск новой версии

Номер версии хранится в одном месте — `apk/version.json`. Его читает сборка и его же
читают установленные приложения, когда проверяют обновления.

1. В `apk/version.json` увеличить `versionCode` и `versionName`, а в `notes` написать,
   что изменилось: по строке на пункт. Этот список человек видит перед установкой.
2. Запустить `pwsh -File device\release.ps1`. Скрипт прогоняет тесты, собирает
   приложение и кладёт его в `apk/kino-pub-<версия>.apk`. Прежний файл с версией он
   удаляет, а новое имя записывает в `apk/version.json` и в ссылку на скачивание в
   `README.md`.
3. Закоммитить изменения и отправить в ветку `main`.

После этого приложения сами предложат обновиться. Задержка — до пяти минут: GitHub
отдаёт файлы из кэша.

### Чего нельзя менять

В установленные приложения зашит адрес, по которому они ищут обновление:
репозиторий `UserNameMoskwin/kino-pub-modern`, ветка `main`, файл `apk/version.json`.
Если переименовать что-то из этого, все установленные приложения останутся без
обновлений.

Имя самого APK брать можно любое: приложение узнаёт его из поля `file` в файле версии.

### Зачем в `apk/` лежит ещё и `kino-pub.apk`

Версии 0.2–0.4 не умеют читать имя файла из `version.json` и всегда скачивают
`apk/kino-pub.apk`. Поэтому там лежит копия версии 0.5: старое приложение обновляется
до неё, а дальше уже само находит свежую версию по имени. Этот файл не обновляется
и не удаляется.

## Ключ подписи

Android ставит обновление поверх только тогда, когда оно подписано тем же ключом, что и
установленное приложение. Ключ лежит вне репозитория; путь к нему и пароль задаются в
`local.properties`:

```
signing.store=<путь к файлу ключа>
signing.alias=<имя ключа в файле>
signing.password=<пароль>
```

Файл ключа и пароль нужно хранить в копии. Без них нельзя выпустить обновление,
которое встанет поверх: всем придётся удалить приложение, поставить заново и снова
войти.

Если этих строк нет, сборка подписывается отладочным ключом Android. Такая сборка
работает, но поверх выпущенной версии не ставится.

## Значок приложения

Значок и баннер для экрана телевизора рисует скрипт: `python device/icons.py`.
Картинки он кладёт в `app/src/main/res/`.

## Что открыто в репозитории

В собранный APK зашит ключ клиента kino.pub из `local.properties`: без него приложение
не работает. Репозиторий открытый, поэтому ключ доступен каждому, кто скачает APK. Это
ключ приложения, а не чей-то аккаунт: данные входа пользователя хранятся только на его
телевизоре.
